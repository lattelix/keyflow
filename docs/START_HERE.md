# START HERE — восстановление контекста без истории чата

Версия спецификации: **1.0, 2026-10-06**. Это рабочий baseline для проектирования, а не утверждение о готовности продукта или одобрении будущих макетов.

## 1. Что строим
Человек садится за пианино, открывает Keyflow, выбирает музыку и видит одно понятное следующее действие. Приложение связывает звук, клавишу, название ноты, нотную запись, ритм и движение по фразе. Учим маленькими музыкальными фрагментами, затем соединяем их. Подсказки можно уменьшать, но всегда вернуть.

Основной пользователь начинает почти с нуля и не обязан понимать MIDI, MusicXML или сольфеджио. Имена нот знакомы, чтение нот — нет. Обучение должно быть понятно на русском; технические идентификаторы и код — на английском. Английский интерфейс — второй locale, без смешивания языков внутри одного экрана.

## 2. Не потерять решения
- Пианино — единственный инструмент v1.
- Web/PWA важен как самостоятельный продукт, включая macOS/Windows через браузер. Нативный desktop-пакет пока не обещан.
- Next.js + React для web, Expo + React Native для iOS/Android, общая TypeScript-логика. Локальные данные; облако не требуется для первой пользы.
- Один responsive-дизайн: одинаковые понятия, действия, состояния, токены. Не растягивать телефонный экран на desktop и не делать три несвязанных UI.
- Бесплатность базового сценария не равна бесплатности любых сторонних каталогов/магазинов/хостинга.
- `Another Love` — цель пользователя и UX reference. Ранее приведённые в чате списки её аккордов не проверены и **не являются музыкальным источником**.
- Первый MVP содержит вручную подготовленный маршрут обучения на оригинальном учебном материале. Автоматический преподаватель для любого файла — позже.
- План не гарантирует профессионального уровня. Техника, выразительность и оценка исполнения требуют отдельного учебного контента и проверки.

## 4. Точность без ложной определённости
В очереди заданы исполнимые задачи для дизайна и web-MVP. Неизвестные технические свойства вынесены в проверочные spikes с конкретными входами/выходами. Native/sync/advanced защищены отдельными воротами; их реализация не начинается до проверки платформ и отдельного пакета решений. Исполнитель не заполняет неизвестные значения догадками.

Спецификация поведения не подменяет текущие версии SDK. Версии выбираются один раз в KF-017 по официальной совместимости и фиксируются lockfile; после этого исполнитель не использует `latest`.
