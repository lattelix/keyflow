## Порядок источников истины
1. Последнее явное решение владельца, записанное с датой и ссылкой/контекстом.
2. Принятые decisions/ADR, product requirements и gate approvals.
3. Спецификации поведения/данных и принятые узлы Figma для внешнего вида.
4. Текущая task card, тестовые спецификации.
5. Реализация. Она не меняет требования своим существованием.

Live inventory используется для утверждений о наличии файлов/макетов; не подменяет целевую спецификацию. Противоречие между текущими источниками не решается автоматическим «побеждает код» или «побеждает Figma».

## Что исполнитель решает сам
Имена локальных переменных, внутреннюю декомпозицию в разрешённых путях, тестовые helpers, устранение очевидного layout-overflow без смены компонента/контракта. Только в пределах принятой карточки.

## Когда остановиться
Неясный владелец ресурса; неизвестная лицензия; платный API/тариф; необходимость нового backend; неподдерживаемый формат без контрактного fallback; изменение учебной логики/stack; отсутствие доказательства прохождения ворот; невозможность проверить ноты/тайминг; конкурирующее изменение того же узла/файла. Записать `BLOCKER` с конкретной причиной, проверенными данными и минимальным решением.

## Шаблон ADR
ID/date/status; проблема; известные факты со ссылками; выбранный вариант; отвергнутые варианты и причины; последствия для UI/данных/offline/стоимости; миграция; тест выхода; кто принял. Один вопрос — один ADR.
