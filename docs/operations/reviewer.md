# Независимая приёмка

Ревьюер не принимает результат по словам автора. Начать с task ID, starting SHA, requirements и diff/узлов, затем самостоятельно проверить каждый пункт `checks`.

## Обязательные вопросы
1. Задача была доступна по зависимостям и воротам? Не изменены ли чужие проекты/платные ресурсы?
2. Все outputs реально существуют? Ссылки открываются? Проверки относятся к этому commit/узлам, а не старому состоянию?
3. Scope не расширен? Public repo не содержит user score/audio, секретов, приватных заметок?
4. UI использует компоненты/токены и сохраняет смысл между размерами? Все ошибки/disabled/empty состояния предусмотрены?
5. Музыкальные события корректны? Неподдерживаемые элементы не проиграны неверно? Evidence source подписан честно?
6. Offline, сохранение и обновление проверены? Ничто не стирает прогресс при reload/update/migration?
7. Есть ли tests и реальные запуск/устройство, когда требовались? Mocked MIDI не физический MIDI.

## Вердикты
- PASS: каждый обязательный check подтверждён; допускается `done`.
- CHANGES REQUIRED: перечислить конкретное расхождение expected/actual, severity, reproduction, evidence.
- BLOCKED: недоступен критический инструмент, ресурс, девайс или решение. Не выдавать условный PASS.

Автоматический planning validator проверяет ссылки/очередь, но не вкус дизайна, педагогическую эффективность, истинность внешнего approval или корректность нот. Эти проверки остаются человеческими/предметными.

## Acceptance design handoff
В Figma есть реальные reusable components, кликабельные переходы, все обязательные состояния и точные node links. Не принять только cover, набор статичных картинок или карточку с подписью «здесь будут ноты». После technical PASS владелец отдельно принимает дизайн и даёт `G-IMPLEMENT`.
