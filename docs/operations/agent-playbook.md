# Playbook — исполнять без догадок

## 1. Восстановить контекст
Открыть AGENTS, STATE, decisions, plan. Проверить `git status`, текущую ветку и remote либо эквивалентными read-вызовами connector. Не смешивать контекст других проектов. Значение поля `pending` сохраняет смысл даже после длинной истории чата.

Запустить валидатор плана. Открыть первую доступную карточку. `next` ничего не меняет и не назначает задачу автоматически. Если предыдущий исполнитель оставил `in_progress`, сначала получить handoff/разрешить конфликт, а не делать вторую копию.

## 2. Проверить право на работу
Все `depends_on` должны быть `done`; все `gates` — `passed` с evidence. Для `in_progress`, `needs_review` и `done` валидатор проверяет это. Задача `blocked` должна иметь причину, а не просто статус.

Запись в публичный repo не означает право писать в любой подключённый Figma workspace. Названия link account не равны workspace: выбирать существующий project file по ключу, не создавать новый в случайной команде.

## 3. Уточнить границы результата
Прочитать `goal`, `requirements`, `inputs`, `allowed_paths`, `steps`, `outputs`, `checks`, `stop_if`. По каждому требованию найти место в результате. Если точного API/версии нет — смотреть toolchain/spike task, а не угадывать сигнатуру.

Не расширять карточку «раз уж рядом»: дизайн-кнопка не повод переписать навигацию, import не повод поднять backend, MIDI не повод включить запись микрофона.

## 4. Работать безопасно
Код: ветка `task/<ID>-<slug>`, маленькие осмысленные commits, читаемый diff. При конкурентных изменениях rebase/merge делать только с пониманием конфликта; запрещены force update и уничтожение чужой работы.

Figma: сначала инвентаризация, затем создание/изменение в нужной странице; сохранять IDs и bindings. Вызывать доступный Figma skill перед Plugin API. Использовать Auto Layout и реальные instances. Не заменять экран плоской картинкой. Не удалять валидные компоненты ради удобства генерации.

Connector: сначала schema, затем read, затем write, затем read-back. При ошибке timeout/partial write нельзя слепо повторять create. Для Git file update нужен актуальный blob SHA; tree commit должен сохранить неизменённые файлы. Для Figma нельзя угадывать nodeId.

## 5. Проверить, а не рассказать
Код: unit/contract/integration/e2e по карточке, реальная production-сборка там, где требуется. Все команды должны существовать в package scripts. Нет shell/инструмента/девайса — NOT RUN, не PASS.

Дизайн: структурная проверка instances/variants/tokens/Auto Layout и визуальная проверка скриншотов в целевых размерах. Скриншот подтверждает внешний вид, но не работающий прототип; клики проверяются отдельно.

Музыка: golden events + сверка нотной записи + аудио/времени, а не «на слух вроде похоже». Ties, rests, voices, tempo и repeats проверять отдельно. Не выводить качество техники по MIDI.

## 6. Отдать на review
Создать report по шаблону, поставить `needs_review`. Ревьюер сверяет требования и состояние независимо, не только summary исполнителя. При замечаниях вернуть `in_progress` или `blocked`; не обходить проверку изменением criteria.

`done` допустим только с artifact evidence и reviewer. Доказательством может быть стабильный repo path, commit/PR или Figma URL; временный screenshot URL нужно сохранить в постоянный артефакт, когда это разрешено.

## 7. Перейти к следующему
После review обновить queue и STATE. Статусы и gates изменяются в одном согласованном изменении. Запустить `validate` и `next` снова. Не утверждать, что последующая зависимая задача уже выполнена.

## 8. Формат блокера
`BLOCKER <task-id>: <причина>` → что проверено → какое требование нарушится при обходе → варианты → предпочтительный минимальный выход → кто должен решить. Если можно продолжить независимую разрешённую задачу, указать её ID; не снимать gate самостоятельно.

## 9. Минимальный контекст для слабой модели
AGENTS + STATE + выбранная карточка + её inputs + последний relevant handoff. Не скармливать все будущие этапы одновременно. Команда `show` печатает полный текущий scope. Попросить модель повторить цель и проверки одной короткой фразой до writes; это не заменяет выполнение.
